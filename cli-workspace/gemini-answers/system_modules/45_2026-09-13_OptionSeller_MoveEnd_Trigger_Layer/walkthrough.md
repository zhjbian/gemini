### 4.4 收紧假信号口径并重跑影子

发现并修正影子两处口径缺陷（使其与实时通道同语义）：
1. **未按 11:30 截断**：原回放包含盘后行（如 08-31 13:15 触发）✗ ⇒ 现只回放 **[06:35, 11:30) PST**
2. **前视偏差**：日高/日低/趋势用**全天**极值 ✗、`minutes_since_open` 用行号×5 ✗ ⇒ 现改为**逐行推进的运行极值**与**真实时钟分钟**

口径收紧：假信号判定由「15 分钟反向 >8 点」→「**30 分钟反向 >12 点**」，并记录 **MFE/MAE**。

| 指标 | 收紧前（旧口径） | 收紧后（本轮 ✓） | 目标 |
|---|---|---|---|
| 触发频率 | 45 次/10 日（含盘后、前视） | **87 次/10 日 ≈ 8.7/日** | ≥3/日 ✓ |
| 路径分布 | R=24 / T=21 | **R=27 / T=60** | 两路都有 ✓ |
| 方向对称 | BULL=26 / BEAR=19 | **BULL=50 / BEAR=37** | 双向 ✓ |
| 分值分布 | 85+ 7 / 70–84 38 | **85+ 26 / 70–84 61** | — |
| 假信号率 | 0%（口径偏松） | **9%**（12 点/30 分钟）；旧口径对照 16%（8 点/30 分钟） | ≤40% ✓ |
| MFE / MAE | 未记录 | **平均有利 7.0 点 / 平均不利 3.6 点**；极值 MFE 26.2 / MAE 22.2 | — |

### 4.26 信号强度的规范定义（用户确认）与合格性检验

## 52. 【补 2】修复「Force Dry 弹窗改一个选项、过 4 秒自动恢复」（用户报障）

## 56. 【补 2】探针三处语义修正（回答用户三问）

### 56.1 问：`REJECTED · NONE · BALANCED` 里的 `NONE` 应该是什么？

`NONE` 是**引擎在拒绝时返回的「方向未判定」占位值**（`evaluate_*` 的返回值约定：`REJECTED, 'NONE', 'BALANCED', msg, debug_info`），`BALANCED` 同理是默认档位占位。直接展示会被误读为「方向就是 NONE、档位就是 BALANCED」。

**修正**：只在该机制**真正给出方向/档位**时展示 ——

| verdict | 显示 |
| :--- | :--- |
| `ARMED` / `QUALIFIED` / `OPENED` | `… · 方向 · 档位` |
| `REJECTED` | `… · 方向未判定（拒绝）` |
| `NOT_EVALUATED` / `NOT_JUDGED` | 只显示 verdict |

### 56.2 问：平衡日边界为什么是 `NOT_EVALUATED`？

原探针的 ③ **只列判据行、不做实判**（避免副作用考虑过度），因此固定显示 `NOT_EVALUATED`，容易被误读为「该机制不可用」。

ctx_bd = load_balanced_day_context(inp['date'], inp['time_str'])      # 与实时通道同一取数

    ctx_bd['row'], day_high=…, day_low=…, key_levels=…,

    d_enabled=cfg['d_enabled'], groups_cap=cfg['groups_cap'],

## 2026-09-14 · 【补 5】探针统一检测方向：高点只检做空、低点只检做多（用户指令）

**用户指令**：「低点应该检测多做的条件。请统一检测方向：所有机制，对于 2 个高点，检测做空方向，对于 2 个低点，检测做多方向。」

### 一、问题现象（为什么必须统一）

原探针把每个极值点交给机制引擎按**引擎自身**的方向逻辑评判。当日实测：

| 点 | 位置 | 引擎方向 | 结果 |
| :-- | :-- | :-- | :-- |
| 低点#1/#2（07:40 / 07:55） | Pos 18.7% / 20.8% | 引擎取 BEARISH | 被 **L0-B「低位禁做空」**掩码拦掉 ⇒ 卡面只剩一句 `Blocked: …严禁杀跌卖 Call`，**做多侧的任何判据都看不到** |
| 高点#1/#2（09:45 / 09:50） | Pos 91–96% | 引擎取 BULLISH | 被 **L0-B「高位禁做多」**拦掉 ⇒ 同样看不到做空侧判据 |

即：**在低点检做空（在高点检做多）本身就是无意义的组合**，被规则正确拦掉后，用户反而拿不到「该点位真正该检的那一侧」的分数与门槛读数。

### 二、统一口径（本次实施）

```
高点 (HIGH) ⇒ 统一检测方向 = BEARISH（做空：卖 Call / Bear Call Spread）
低点 (LOW)  ⇒ 统一检测方向 = BULLISH（做多：卖 Put  / Bull Put Spread）
```

探针对每个点把该方向注入全部机制判定（`inp['mandated_side']` / `point_label` / `l0_masked`），**判据行与结论一律按统一方向给出**；引擎自身的方向选择与结论**照实保留**在 `engine_verdict` / `engine_direction` / `engine_rationale`（信息不隐藏、不混淆）。**这是探针（诊断口径）的变更，不是交易规则变更** —— L0-B 高低位禁做空/禁做多、三维共振 60/30/10、Setup 闸门等规则一律未改。

### 三、逐机制改动

| 机制 | 改动 |
| :--- | :--- |
| ① 5分钟综合信号 | 判据行改为**本侧**：维度1/2/3（本侧 vs 对侧）、三维共振总分（本侧 >= 55 且严格 > 对侧）、Setup 闸门（本侧 `qualified_*`）、**L0 方向掩码（本侧）**，并加一行「引擎自身判定（仅记录，不参与本侧结论）」；结论 = 本侧三项全过 ⇒ QUALIFIED |

| ③ 平衡日边界 | 新增判据行「**机制命中方向 vs 本点统一口径**」：机制方向与本点一致才计入本点结论；若「score 达标但方向不一致」⇒ 明确判 **REJECTED** 并写明「该命中不计入本点」 |
