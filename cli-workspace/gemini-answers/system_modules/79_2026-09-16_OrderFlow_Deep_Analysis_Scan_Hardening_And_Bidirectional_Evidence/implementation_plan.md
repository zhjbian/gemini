- **日期**：2026-09-16
- **归属模块**：**M17. Adam Set 社媒信号研判与事件研究系统**（交叉引用 M03 DOM 200档深度盘口、M02 订单流大单与微观结构量化分析引擎）
- **触发场景**：用户要求用 `order-flow-deep-analysis` 验证 Adam Set 2026-09-16 两条看空帖（07:21:43 / 07:42:06 PT）发布前后的 order flow 证据。

## 1. 起因：首次运行得到的是「假结论」

首次按 skill 标准流程对 `2026-09-16 07:21` 窗口运行 `run_analysis.py`，产出报告结论为：

> 「方向 · 全窗：全窗 imb ±5 均值 -0.045 · 偏空 43% ... 两源分歧 ⇒ 谨慎 ⚠️」

但报告「DOM 时间演变」表的 T−30′ / T−15′ / T−5′ / T0 四个时点**全部指向同一个快照 `07:00:01`**，且时间线里出现 3 个「DOM 盲区」槽。即：**盘口层几乎完全没有数据，却照常生成了看起来完整的结论**。

这属于「静默降级」类缺陷：不报错、不中断，只是把最重要的证据层悄悄丢掉。若不深究，会把「DOM 盲区」误读成「两源分歧」，从而得出与事实相反的结论。

## 2. 根因定位：单行脏时间戳触发提前 `break`

### 2.1 现象与定位过程

| 步骤 | 动作 | 结果 |
| :--- | :--- | :--- |
| ① | 全量扫描 `ES_20260916_DOM.csv.gz`，按分钟统计覆盖 | **39,689,858 行 / 747 个分钟**，连续覆盖 `06:48 → 14:00`、`14:45 → 15:06`、`15:08 → 16:50`、`16:53 → 20:00` |
| ② | 直接调用 `dom_analysis('2026-09-16', 07:21)` 打印 `_series` | 仅 `06:48–07:00` **13 个分钟** |
| ③ | 打印 `07:00:01` 之后的第一个不同时间戳行 | 命中异常行 `['17895672011789567279736', 'BID', '0', '7682.00', '75', 'ESZ26']` |
| ④ | 计算该行 `_pt()` | `int(17895672011789567279736 // 1000 - 7*3600) % 86400` = **31679 = 08:47:59** > `t0_sec`(07:21) ⇒ **立即 break** |

### 2.2 缺陷代码（修复前）

```python
try:
    t = _pt(row[0])
except Exception:
    continue
if t > t0_sec:
    break          # ← 单行异常时间戳即终止整个扫描
```

- 该异常行是**两次时间戳被拼接**（`1789567201` + `1789567279736`），属 MW 导出侧的数据拼接瑕疵，不是解析器 bug。
- 但解析器**没有区分「单行异常」与「已越过窗口端点」**，把前者当成后者。
- 位置：`PyTools/jobs/adam_dom_analysis.py`（2 处）、`adam_tick_analysis.py`（1 处）、`adam_signal_deepdive.py`（2 处），共 **5 处**。

### 2.3 影响面界定（实测）

| 文件 | 异常回跳行数 | 说明 |
| :--- | ---: | :--- |
| `ES_20260916_DOM.csv.gz` | **2** | 第 1 处导致 `07:00:01` 后 DOM 全丢；第 2 处位于 `07:30:42`（前一有效 `12:50:42`） |
| `ES_20260916_TICKS.csv` | **0** | 当日 tick 未受影响；但代码路径同源，属潜在风险 |

⇒ **只要某日 DOM 文件含 1 行此类脏数据，该日「t0 之后」的盘口层就整段丢失**，且丢失起点恰好是脏行的位置（可能很早）。

## 3. 第二、三个问题（在修复①之后暴露）

### 3.1 带宽失衡「买侧/卖侧」措辞与符号脱钩（显示缺陷）

`adam_dom_analysis.py` 的带宽解读列把措辞**硬编码**：

```python
("<span>买侧占优 ✓</span>" if (imb) * sign > 0.02
 else ("<span>卖侧占优 ✗</span>" if imb * sign < -0.02 else "接近平衡"))
```

`sign = 1 if aside=='bullish' else -1`，而 `imb = (买挂单 − 卖挂单)/(买+卖)`（`>0` = 买侧厚）。
⇒ 在 **bearish 视角（sign = −1）** 下，`imb = −0.218`（卖侧厚）会判定 `imb*sign = +0.218 > 0.02`，被打印成 **「买侧占优 ✓」**——**买卖方向整表倒置**。同类问题另见 2 处解读文案（§4 修正）。

### 3.2 引擎 `imb_*` 与原始 DOM 复算口径不一致（数据源问题）

`run_analysis.py` 的窗口级 DOM 聚合 `dom_window_profile()` 采取「**DB 扁平列 `imb_short` / `imb_mid_short` 优先，缺失才回退原始复算**」。两者实测不一致：

| 配对方式 | n | 符号一致率 | Pearson r | 均值（引擎 / 复算） |
| :--- | ---: | ---: | ---: | :--- |
| 同分钟配对（2026-09-16 07:45–08:45） | 13 | **53.8%** | **0.352** | −0.0022 / −0.0481 |

⇒ 符号一致性接近抛硬币。**混用两套口径会让窗口级 DOM 方向结论不可信**；报告里「全窗 imb ±5 均值」实际主要是引擎口径，不能当作"盘口方向"来读。

## 4. 实施方案

### 4.1 修复 ①：脏时间戳防截断（5 处）

```python
_beyond = 0
for row in rdr:
    ...
    if t > t0_sec:
        # ★ 单行脏时间戳会让 break 提前截断整个窗口 ⇒ 改为「连续越界行」达阈值才 break
        _beyond += 1
        if _beyond > 50000:
            break
        continue
    _beyond = 0
```

- 阈值取 **50000 行**：正常越界时多读约 0.6 分钟盘口（可忽略），而异常行是**孤立**的，其后有效行会把计数归零。
- 同时修复 `adam_tick_analysis.py`、`adam_signal_deepdive.py` 的同源路径。

### 4.2 修复 ②：`_band_label()` 让措辞跟随符号

新增 helper，**买卖措辞按 `imb` 实际符号走，✓/✗ 仍按「是否支持待验证方向」判定**；并修正 2 处受同因影响的解读文案（±5 档「买/卖挂单多出」措辞、±5 失衡演变「由空转多」措辞）。

### 4.3 纠正 ③：DOM 结论一律用原始复算

- 本报告的 DOM 结论**全部改用** `_series` 的 `bid_5 / ask_5 / imb_5`（纯复算），不使用引擎 `imb_*`。
- 建议（未实施）后续在报告中把两套口径**并列显示**而非静默取优。

### 4.4 新增：双向证据维度（**描述性 · 阈值未标定**）

在 `evidence.dims` 下新增两个多空对称维度，**只输出证据、不进入 `patterns.py` 判定**：

| 维度 | 字段 | 定义 |
| :--- | :--- | :--- |
| 吸收度 | `absorption.ad_ratio` / `absorption_side` | 窗口净 Delta ÷ 窗口价格位移（手/点）；`\|位移\| < 1 tick` ⇒ `null` |
| 大档位/盘口迁移 | `wall_migration.imb5_drift` 等 | ① 近端 ±5 失衡前后半段漂移（主口径）② 最大买/卖档距盘口距离漂移 + 手数变化 ③ **瞬时事件**（≤5 分钟内大额档向盘口收拢 ≥2 ticks 且增仓 ≥40 手，附 `reverted_quickly` 假挂单标记） |

**刻意不设阈值**，理由见 §5。

## 5. 为什么这两个维度「不能」直接当判据（关键约束）

标定过程中发现决定性反证：

| 案例 | 位置 | `absorption_side` | `wall_migration.read` | 前向结果 |
| :--- | :--- | :--- | :--- | :--- |
| 2026-09-14 07:54 | **低点** | `buy_absorbed`（净 +2469 / 位移 −23.5） | `bid_side_migration` | **上涨** mfe60 **+42.5** |
| 2026-09-16 07:42 | **高位** | `buy_absorbed`（净 +2900 / 位移 −5.5） | `bid_side_migration` | **下跌 103 点** |

⇒ **同一组维度取值，在相反结局上同时出现**：
1. **吸收度本身没有方向性**，必须与「位置」（`low_pos_pct` / `high_pos_pct`）联读：低位⇒承接反转，高位⇒派发。
2. **`wall_migration.read` 未通过方向性验证**（两侧都为 `bid_side_migration`）⇒ 只描述盘口形态变化。
3. `reverted_quickly = true` 是**反证**而非正证：09-16 07:10 的 150 手买档在 07:11 即回落至 81 手，属诱导性挂单。

**纪律**：要升级为判据，必须先积累「**同形态相反结局**」的配对样本，再用配对差值标定；在此之前只进 `evidence.dims` 供人工审阅。

## 6. 验收口径

1. `2026-09-16 07:21` 窗口的 DOM `_series` 由 **13 分钟** 恢复为 **34 分钟**（06:48–07:21，受 exporter 起始时间限制）。
2. `06:48–08:52` DOM 复算覆盖 **125 分钟**，可用于卖墙持续性统计。
3. 报告带宽解读列在 bearish 视角下措辞与符号一致（−0.218 ⇒ 「卖侧占优 ✓（支持该方向）」）。
4. `evidence.dims` 在 bullish / bearish 两种视角下均输出完整、语义一致。
5. **回归**：`baseline_pair.py --selfcheck` 复现文档既有值（09-14 07:54 `A 型 +9/9`、mfe60 +42.5；09-14 07:40 `A 型 +7/9`、+31.5；09-15 全天无候选通过门槛）⇒ 证明修复对无脏数据的日期**零影响**。
