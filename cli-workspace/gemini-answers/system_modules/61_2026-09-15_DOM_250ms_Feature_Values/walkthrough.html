6. 已知限制（据实）

  1. 样本不足：250ms 档 ≈ 1 天；即便累积，250ms 也只在 08-21/08-24/09-14 出现（09-15 已回 500ms）⇒ 需要按天累积并自动分 cohort（本模块已按 iv_med_ms 自动分）。

8.1 口径（用户指定：DOM pattern 现阶段只做短期）

目标变量改用 TICKS 1 分钟价路径（dom_day_targets.py）计算，解决引擎 5 分钟行在 08-xx 仅 14–16 根/天的问题：

变量定义

8.2 ★ 关键方法论点：次日只能做日级检验

next_ret 在同一交易日内是常量 ⇒ 槽位级"次日 edge"只能反映桶落在哪些日子（day-mix artifact）。

实测：未加同日配对时，槽位级桶出现 +26.6pp / −24.0pp 的"次日 edge"；加入同日配对与日级口径后，

这些 edge 全部塌到 ±7.4pp 以内（当天余下最强的 近端卖盘挂单中位 mid = −7.4pp，且只在 2/14 天为正）。

⇒ 已实现：① 槽位级只用同日配对测当天余下；② 次日一律走日级检验（日指标 = 当日该特征的原始均值 /

日高值占比 = 当日高于全局 67 分位的槽位占比 / 日级复合分）；③ 每项附留一天 min|ρ| 脆弱性标记。

同时修掉一个自检发现的伪结论：早先"日级复合分"用当日内 z 分求日均，而日内 z 分的日均恒为 0

⇒ 排名只在数值残差上做，产出的 ρ=−0.80 是纯人工产物（已废弃并改为原始日均跨日 z）。
