# 实施计划 (Implementation Plan)

**模块编号**: 42
**归档目录**: `42_2026-09-11_LIVE_Primary_PnL_Calendar`
**发生日期**: 2026-09-11
**核心模块名称**: 期权卖方日历盈亏 LIVE 主显示改造 (LIVE-Primary PnL Calendar & Monthly Badge)
**涉及技术栈**: Flask API 语义核对 / Jinja 模板内联 JS / Calendar Cell Rendering / Light-Theme UI

## 1. 需求（用户 2026-09-11 指定）

盈亏展示**以 LIVE（实盘）为主**：

- **日历单元格**：第一行 = **LIVE 当日 PnL**；第二行 = `DRY $x.xx All $y.yy`，**字号小一号**。示例：
  ```
  $14.00
  DRY $0.00 All $14.00     ← 小一号字
  ```
- **月度徽标**：显示 `月度盈亏: LIVE / DRY`，其中 **DRY 数值字号小一号**。示例：`月度盈亏: +$101.00 / $123.00`

## 2. 数据口径核对（实施前取证）

`GET /api/option_seller/calendar_pnl` 每日载荷：`pnl` = **All（LIVE+DRY）**，`live.pnl` / `dry.pnl` 为分项。实测：

| 日期 | LIVE | DRY | All(=pnl) |
| --- | ---: | ---: | ---: |
| 2026-09-08 | 0.00 | 75.00 | 75.00 |
| 2026-09-10 | 87.00 | 0.00 | 87.00 |
| 2026-09-11 | 14.00 | 0.00 | 14.00 |

2026-09 月度合计：**LIVE $101.00 / DRY $347.00 / All $448.00**（与用户示例中的 `+$101.00` 一致，佐证 LIVE 主值口径正确）。

## 3. 方案

1. 单元格：`cal-pnl-val` 改为 LIVE；`cal-trade-count` 改为 `DRY … All …`，并拆成两个 `white-space:nowrap` 分组，使宽格单行、窄格（双月视图）整齐折两行而非断成三行。
2. 月度：新增 `monthLivePnl` / `monthDryPnl` 累计；徽标主值取 LIVE（保留 `+` 号风格），其后以 `0.82em` 小字号附 `/ $DRY`。
3. 配色：单元格 win/loss/even 与月度徽标色阶改为**跟随主显示值（LIVE）**，避免"绿底显示 $0.00"的自相矛盾。
4. 正负号：单元格按用户示例采用"仅负数带 `-`"；月度主值沿用既有 `+` 号风格。

## 4. 验收标准

| # | 项 | 判定 |
| --- | --- | --- |
| 1 | 单元格首行为 LIVE | 首行值 == `live.pnl`，且与配色一致 |
| 2 | 次行为 DRY + All 且字号更小 | 次行文本 `DRY $.. All $..`，`font-size` < 首行 |
| 3 | 月度徽标为 LIVE / DRY 且 DRY 更小 | 主值 == `Σlive`，附值 `font-size` 约为主值的 0.82 倍 |
| 4 | 窄格不出现三行碎断 | 双月视图下小号行按"DRY 组 / All 组"整齐排版 |
| 5 | 不污染规则手册 | 属 UI 展示规范，**不写入**规则手册（依据既有裁定：仅决策性规则入库） |
