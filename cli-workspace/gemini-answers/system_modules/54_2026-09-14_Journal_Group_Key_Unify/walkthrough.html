账本「订单组合」分组键统一 · 验收报告

2026-09-14 · 归档 54_2026-09-14_Journal_Group_Key_Unify

用户报障：「过滤结果里 #11 #12 是一个单，但没有显示在自己的组里」 —— 同一次开仓的两批各自单独成行、无组头，批次徽标退化成「单批次」。

1. 根因：三处分组「键」口径不一致

group_order_id 是开仓路径写入 entry_evidence 的同组共享键（DRY 与 LIVE 皆然）； 仪表盘「活跃持仓」早已用它，但账本与 TV 生成器只看三个启发式：

位置旧口径结果
账本 renderHistoryTable()order_id 基名 → DRY 时间戳 → 同 strikes 且开仓 ≤ 3 s✗
TV 生成器同上（少 DRY 分支）✗
仪表盘「活跃持仓」group_order_id → order_id 基名 → open_time+strikes✓

LIVE 场景必然落空：两批各自持有独立券商 order_id（实测 1007916750080 / 1007916750091，无 -1/-2 后缀）， 开仓时间又差 4 秒（09:33:29 / 09:33:33 = 4 s > 3 s 阈值）⇒ 三条启发式全不命中 ⇒ 同一次开仓被拆成两个「单成员组」 ⇒ isTwinGroup=false ⇒ 组头不渲染。 （DRY 单因 order_id 形如 DRY-<ts>-1/-2 基名相同而侥幸正常 —— 缺陷长期未被发现的原因。）

id 245  order_id 1007916750091  open 09:33:33  T2  764/766  group_order_id = DRY-1789403609   ← 同键

2. 修复（三处统一，权威键优先）

// 账本 renderHistoryTable()
const tAuthKey = t.group_order_id || (t.entry_evidence && t.entry_evidence.group_order_id) || null;
const authGrpKey = tAuthKey ? ('GRP:' + tAuthKey) : null;
let matchedGrpKey = (authGrpKey && groupsMap.has(authGrpKey)) ? authGrpKey : null;
…
for (const [existingKey, existingTrades] of (matchedGrpKey ? [] : groupsMap.entries())) { …既有启发式… }
const grpKey = matchedGrpKey || authGrpKey || tOidBase || `${t.open_time}_…`;
  • 命中权威键即跳过启发式（? [] : …）⇒ 既快又不会被错误并入别组；
  • 无键历史行仍走原启发式 —— 行为与改造前逐行一致（测试锁定）；
  • GRP: 前缀避免与 order_id 基名空间冲突；单批仍自成一组（不误合并）；
  • 后端 /api/option_seller/trades_by_date payload 同时补回 group_order_id（与持仓序列化同口径）；
  • TV 生成器同口径 ⇒ Pine 里的「订单组合」编号与账本/仪表盘完全一致（副带修正模块 53 的组标签）。
