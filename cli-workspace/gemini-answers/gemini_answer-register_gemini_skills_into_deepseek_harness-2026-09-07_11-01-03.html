操作目标与来源

将 Gemini CLI / Antigravity 的全部自定义 agent skill 从源目录 /Users/zhijiebian/.gemini/skills（共 13 个）注册到 DeepSeek Harness（DSH）的 user-agents skills 体系，目标布局为 ~/.agents/skills/<name>/SKILL.md（$DSH_AGENTS_HOME 为空时缺省 ~/.agents）。DSH 装载器要求：每个目录内的 SKILL.md 必须以合法 YAML frontmatter 开头（首字符 ---），且包含 name（与目录同名）与 description 字段。

修复项明细（仅改 DSH 副本）

  1. 4 个源文件缺少 frontmatter（内容直接从正文开始，装载器不会索引）：options-flow-analysis、spike-analysis、stock-analysis、stock-news。已在其 SKILL.md 头部补上 ---\nname: ...\ndescription: ...\n---，description 依据各技能正文首段归纳。

  2. stock-daily-analysis-deprecated 文件头损坏：原文件第一行是 [^1]---（残留 footnote 标记），且 frontmatter 内 name: stock-daily-analysis 与活跃版 stock-daily-analysis 同名冲突。已剥离 [^1] 前缀并把 name 改为 stock-daily-analysis-deprecated 以对齐目录名、避免冲突。

  3. dark-pool-analysis 源目录没有 SKILL.md（仅有 references/ 回测文档与 scripts/ 脚本）。按实际内容合成一份最小 SKILL.md：description 描述其基于本地 BBTrading MySQL（DarkPoolTradeAgg）对暗池成交量/名义额（如 TSLA）做回测与 session conviction audit；正文列出 scripts/backtest_dp_volume.py、scripts/backtest_dp_notional.py、scripts/generate_tv_dp.py 及 references/ 下回测文档的用途。若存在权威版定义，替换该文件即可。

过程异常与原子重建

批量 cp -R 复制后出现异常：~/.agents/skills 下 10 个目录一度消失，而 whale-trade-analysis 的内容被平铺到 skills 根目录（根级出现 SKILL.md（name=whale-trade-analysis）、.env.example、.venv、images/、references/、scripts/），疑似外部同步/装载器并发干扰。处理方式：删除后一次性原子重建全部 13 个目录（单条命令完成 rm -rf + 重新复制 + frontmatter 规范化），最终校验 13/13 全部为规范布局（文件首行 ---、name 与目录一致），无根级散落文件。

目录刷新确认

重建完成后，DSH 会话的 available skill catalog 完整列出全部 13 个 skill（此前只识别出 gem-doc 与 whale-trade-analysis，原因是 catalog 刷新为增量/异步，且不合规 frontmatter 的目录会被跳过）。

使用注意

  • 注册后即可在 DSH 会话中按技能名直接触发（如"用 whale-trade-analysis 分析"）。
  • 各 SKILL.md 正文普遍硬编码了本机绝对路径（如 ~/.gemini/skills/<name>/scripts/*.py、/Users/zhijiebian/Documents/Workplace/PycharmProjects/BBTrading、~/.gemini/cli-workspace/gemini-answers），均为绝对路径，在本机可直接执行；换机器需同步迁移这些外部项目与路径。
  • 技能描述措辞多基于 Gemini CLI 语境（如 gem-doc 的"保存当前 Gemini 会话的回答"），在 DSH 中触发时由 agent 从当前对话重建问答内容再调用脚本，语义等价。
