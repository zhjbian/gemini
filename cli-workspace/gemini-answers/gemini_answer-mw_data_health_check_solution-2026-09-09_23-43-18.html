一、巡检脚本 PyTools/jobs/mw_data_health_check.py

五层判定

层 检查 状态
L1 存在性 交易日应有文件是否存在 MISSING
L2 完整性 全流解压校验（权威判定） CORRUPT
L3 体积 默认只判退化(<1MB)；--strict-size 才启用比值 EMPTY/SUSPECT
L4 时效 生成滞后 > 30h（仅最近 3 个交易日） STALE
L5 内容 --lines 时检查 TICKS 行数 SUSPECT

关键设计决策（实测驱动）：

  • 实测全量 gzip 校验只要 0.47s / 100MB → 可以对每个文件做完整校验，不需要抽样，判定 100% 可靠。
  • 实测 DOM 合法体积跨度 7MB ~ 798MB（100 倍） → 体积启发式误报严重，故默认关闭比值判定，只保留"退化体积"兜底。这是第一版踩的坑，已修正。

鲁棒性

  • 单文件独立 try/except，任何异常都收敛为"状态"而非中断整体
  • TCC 前置检查：目录不可读时直接退出（码 3），绝不把全部文件误报为 MISSING
  • 幂等 UPSERT（唯一键 ticker+kind+data_date）
  • 报警去重：同文件同状态当天只报一次（实测二次运行 → "无新增异常 ✓"）
  • 只读，绝不改动源文件
  • 退出码：0=全健康、1=有异常、2=目录错、3=权限错

报警

  • 落库 bb_trade.mw_data_file_health（49 条，可直接做 Web 看板）
  • --email 发 HTML 汇总邮件，含异常明细表 + 信号影响面表 + 需重导清单

⚠️ 三、需要做一步手动授权（macOS TCC）

实测确认：launchd 进程完全读不到 ~/Documents（脚本和 MW 数据都在里面）：

/bin/bash: .../mw_data_health_check.sh: Operation not permitted
ls: .../MotiveWave_OrderFlow_Data/Raw: Operation not permitted

（当前终端能跑，是因为 Terminal 已有权限。）

请授权一次（GUI 操作，无法脚本授予）：

系统设置 → 隐私与安全性 → 完全磁盘访问权限 → 「+」
  Cmd+Shift+G 输入：
  /Library/Frameworks/Python.framework/Versions/3.11/Resources/Python.app/Contents/MacOS/Python
  添加并打开开关

plist 特意改成直接调用 Python、不经 bash，并把日志放到 ~/Library/Logs/bbt-mw-health.log（非受保护目录）—— 这样只需给这一个 Python 授权，不用给 /bin/bash（权限面更窄）。

授权后验证：launchctl start com.bbt.mw-data-health 然后看 ~/Library/Logs/bbt-mw-health.log。

6. DB 表结构 mw_data_file_health

字段 说明
data_date / ticker / kind 唯一键（数据日 / ES·NQ / DOM·TICKS）
status OK / MISSING / CORRUPT / SUSPECT / STALE / EMPTY
exists_flag / size_bytes / size_ratio 存在性与体积
decompressed_bytes / line_count 解压后字节数与行数
mtime / gen_lag_hours 生成时间与滞后小时
error_detail 失败详情
checked_at / last_alert_at 巡检时间与报警去重时间戳
