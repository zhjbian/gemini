0. 评估范围与方法

  • 规则来源：交易系统核心规则手册 第一部分（5分钟两步判定法：方向准入 + 1~10 强度打分 + DOM 200档 + Gamma 联动）。

1. 总体结论（一句话）

理论框架方向正确、防御设计成熟，但实现上存在若干“把近似当作精确”的硬伤，且整套规则是未经验证的手工阈值系统——作为“决策支持/风险过滤”可用，作为“统计边缘”尚不成立。

2. (1) 现在理论框架是否合理

合理，且相当有层次。它本质上是一个“多因子微观结构专家系统”，可逐项映射到标准理论：
- Delta / Cumulative Delta（inc_delta = +size if ASK else -size）＝标准 order flow 的主动量净额。
- DPER（价格推进效率）本质是每单位 Delta 的价格冲击，与 Kyle λ / Amihud 非流动性 / OFI 价格冲击同族。
- weighted_imbalance（多梯队盘口加权失衡）＝Cont–Kukanov–Stoikov 的订单流失衡（Order Flow Imbalance）。
- book_flip / vacuum / stack / iceberg＝盘口动力学的直觉刻画。
- Gamma Regime（正/负 Gamma、Call/Put Wall、Gamma Flip、pinning）＝标准 0DTE 做市商对冲模型。
- 两步判定 + 一票否决 + 中性细分是防御性很好的设计，符合风险管理优先原则。
但框架的合理是“定性合理”，不是“定量成立”：40+ 阈值（±3000/±4500/±5000/±800/±500、0.85/1.40/1.15/0.70、0.20/-0.20、20s、1.5、2.0点…）人工拍定，没有配套样本外回测证据。应定位为 expert-system overlay（决策辅助与风险闸门），而非已校准的 alpha 模型。

3. (2) 哪些地方有错误（可定位）

  • E1（最严重）DPER 符号归一化使“底背离/顶背离”判定近乎失效：dper_30m = price_change/(net_delta/1000)，价格与 delta 同号时 DPER 恒为正，net_delta_30m<=-3500 and dper_30m>-1.5 里 >-1.5 几乎恒真 → 退化为纯“大额抛压”，背离逻辑名存实亡。✅ 已完成
  • E2 “iceberg”不是冰山检测：实际是 abs(b_chg)<=3.0 且高成交低位移的吸收代理，未检测隐藏量 refill。✅ 已完成
  • E3 spoof 把“被打掉”误当“撤单”：diff_bids<-50 记为撤单，但深度减少也可能是市价打穿，未结合 trade print 区分 → 会误封杀真实抛压。✅ 已完成
  • E4 文档与代码盘口权重不一致：文档§2(5)写 50/30/15/5，§6(1)写 50/35/10，代码 50/35/10/5（远墙 45/25/10/20）。✅ 已完成
  • E5 price_position_pct 用递归扩大的 RTH 高/低，早盘严重失真。⏳ 未处理
  • E6 绝对阈值未做量级/波动率归一化（±3000/±800 等裸合约数，高/低成交量日含义不同）。⚠️ 部分完成
  • E7 新旧两套引擎并存（旧 delta_pct_vol+cond_a..d 启发式 vs 新 tiered scoring），双真源/死代码风险。⚠️ 部分完成
  • E8 次要：iceberg 门槛 last_5m_delta>=-300 退化；book_flip 用粗糙均值比；vacuum nb/5<10 粗糙；600 网格是前向填充假设。⏳ 未处理

4. (3) 哪些地方可以改进（优先级排序）

  1. 修复 DPER：滚动回归取 Kyle λ 或 |price_change|/|net_delta| 的 z-score，让背离真正要求价格不确认。✅ 已完成
  2. delta 归一化：主特征切到 delta_pct_vol / delta/volume / delta/ATR，阈值用分位数。⚠️ 部分完成
  3. spoof 加“成交 vs 撤单”判别，或改 OFI。✅ 已完成
  4. iceberg 正名（absorption_proxy）或实现 refill 检测。✅ 已完成
  5. 用 TPO Value Area(POC/VAH/VAL)/Opening Range 替代递归高/低。⏳ 未处理
  6. 消除 doc-code 漂移 + 清理旧引擎，规则集中到版本化 config。⚠️ 部分完成
  7. 整合 Gamma Cushion 到 OF 打分（近 Call/Put Wall 8–15 点时降级/拦截）。⏳ 未处理
  8. 加 CVD 多周期背离（价格新高/低而 CVD 不新高/低）。⏳ 未处理
  9. 输出置信度与可追溯性（setup 分支 + veto 原因 + 阈值版本号）。⚠️ 部分完成

5. (4) 还缺少什么重要的东西

微观结构层：VPIN（订单流毒性）、OFI/queue imbalance、真实冰山 refill、执行质量/参与率归一化。
拍卖理论层（最大缺口）：Market Profile 的 POC/Value Area/TPO/单印/Excess/差高低点；Balance vs Imbalance/旋转识别。
统计/工程层：样本外回测与校准、Live vs Backtest 对账、精度/召回/时效衰减、波动率/成交量/流动性日历自适应、每信号头寸规模、数据质量管线、可复现版本化。

6. (5) 改进方案（分阶段路线图）

  • Phase 0 正确性修复（1–2 周）：重写 DPER 背离、spoof 加成交/撤单判别或改 OFI、iceberg 正名、统一盘口权重、清理旧路径、阈值外置+版本号写入 verdict。✅ 已完成
  • Phase 1 归一化与拍卖参考系（2–3 周）：delta 用 delta/volume、delta/ATR 分位数；引入 TPO Value Area + Opening Range 作位置锚；波动率/成交量 regime 门控。⚠️ 部分完成
  • Phase 2 补齐缺失测度（3–4 周）：接入 OFI、VPIN、真实 iceberg、CVD 多周期背离；Gamma Cushion 作为 OF 一级过滤器。⚠️ 部分完成
  • Phase 3 验证与校准（持续）：backtest 框架，逐 setup/逐阈值桶的命中率、胜率、时效衰减、walk-forward；产出《分层校准报告》并反推删减冗余加分项。⏳ 未处理
  • Phase 4 集成与工程化：OF 信号→头寸规模打通；规则 config 版本化+部署；drift 监控（规则改动对历史信号 diff）。⚠️ 部分完成
