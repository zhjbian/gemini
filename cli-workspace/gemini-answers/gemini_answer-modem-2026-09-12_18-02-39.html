四、建议的对比流程（否则结论会失真）

# 做法 原因
1 插上网线（任一 Ethernet Adapter）再测 排除 Wi-Fi 干扰，最关键一步
2 每个配置连测 3 次取中位数 实测单次波动达 23%
3 同一时段测（避开晚高峰） Comcast 高峰降速常见
4 测延迟与抖动同样重要（不只是 Mbps） 你的 DOM/Tick 管道 + 实时提醒吃的是延迟稳定性
5 关注 Responsiveness 指标（>1000 RPM 为佳，现在 148） 缓冲膨胀会让盘中操作"顿"

结论

ARRIS Surfboard S34 换上后，下行 58.7 → 207–230 Mbps（约 3.5×）、上行 22.5 → 42–43 Mbps（约 1.9×）、缓冲膨胀 404–513 ms → 207–246 ms（改善约 2×）。原先的判断得到证实：套餐本身 ≥200–250 Mbps，是旧 modem SB6141（DOCSIS 3.0，8×4 通道） 把速率压在 ~75 Mbps；同时换机重启后路由器重选信道（36 → 157），Wi-Fi 信号由 −81 dBm / SNR 8–9 dB 改善为 −70 dBm / SNR 19–25 dB。残留的缓冲膨胀（246 ms，Medium）几乎可确定来自 Archer C7 路由器无 SQM。

二、三点解读

  1. 套餐速度被旧 modem 压住了：SB6141 为 DOCSIS 3.0 / 8×4 通道绑定（2013 年机型），实际只能送达约 75–150 Mbps。换 S34（DOCSIS 3.1）后立刻解锁到 207–230 Mbps，说明套餐本身就 ≥200–250 Mbps。换机收益超出预期：不只是延迟改善，而是速率量级提升。
  2. 缓冲膨胀改善但未根治：513 → 246 ms，评级由 Low 升为 Medium。剩余部分几乎可确定来自 TP-Link Archer C7（Wi-Fi 5，无 SQM/QoS 智能队列），而非 modem。
  3. Wi-Fi 意外改善：信号 −81 → −70 dBm、SNR 8 → 19–25 dB、发送速率 260 → 390 Mbps、信道由 36 变为 157。原因为换机断电重启后路由器重新选信道（避免拥挤频段）。但 −70 dBm 仍偏弱（理想应 >30 dB SNR），属位置问题。

大品牌中支持 SQM 的路由器对比（追加）

本节要点

判定标准

「支持 SQM」= 支持真 AQM（cake 或 fq_codel），不是"限速式 QoS"、不是"游戏加速/设备优先"。

一、大品牌 SQM 支持情况

品牌 品牌体量 SQM 类型 是否真 AQM 备注
Ubiquiti（UniFi） 上市公司 · prosumer 头部 Smart Queues 是，fq_codel 系 UCG 系列 / UDM / UDR；UDR 自带 Wi-Fi，其余需另配 AP
MikroTik 网络设备大厂（ISP/企业广泛使用） RouterOS 原生 cake 是，cake + fq_codel + codel 必须处理 FastTrack 会绕过队列的问题；学习曲线陡
Netgear Nighthawk Pro Gaming（DumaOS） 消费大牌 Anti-Bufferbloat 是 仅 XR 系列（XR1000/XR500 等）；普通 Nighthawk 无
Firewalla 中大型 prosumer Smart Queue 是，cake/fq_codel 开 SQM 后吞吐有折损；价格偏高
Netgate（pfSense/OPNsense） 企业级 cake/fq_codel limiter 是，最强 最灵活稳定；需自行配置 + 另配 AP
GL.iNet 细分专业厂（小） OpenWrt SQM 是，cake 内置网页开关，不用刷机

二、明确不满足的大牌

品牌 原因
TP-Link（消费级） 只有限速式 QoS；实测启用后上行 −43%、延迟零改善；Omada 企业线也没有 cake
ASUS Adaptive QoS 口碑差；原生固件无 cake
Netgear 非 XR 系列 只有常规 QoS，无 Anti-Bufferbloat
Synology / Linksys / Google Nest / eero 无用户可用的真 AQM
ISP 网关（Xfinity 自带） 无用户可控 AQM（另有 LLD 路线，见下）

三、按需求（250 Mbps + 低延迟 + 2.5G）的排序

排序 方案 体量 说明
1 UniFi UCG-Ultra + U6 Pro/U6+ 大厂（上市） Smart Queues 省心 + 2.5G WAN + 稳定；缺点两个设备、需 Unifi 生态
2 MikroTik（hAP ax³ / RB5009） 网络大厂 原生 cake、性能余量足、便宜；配置门槛高
3 Netgear Nighthawk Pro Gaming（XR） 消费大牌 Anti-Bufferbloat、一体化、界面友好；Wi-Fi 世代偏旧、2.5G 口要挑型号
4 Firewalla（Gold/Purple） prosumer 功能强；开 SQM 掉吞吐、价高
5 Netgate + pfSense/OPNsense + AP 企业级 最强最自由；最折腾

四、替代路线

Comcast 新一代网关（XB8 等）在支持 Low Latency DOCSIS（LLD）的档位上由 ISP 侧做 AQM，即"不买路由器也能降缓冲膨胀"。但这与自购 S34（DOCSIS 3.1 modem）的路线互斥：用自有 modem 就没有 ISP 侧 AQM。属需核实套餐/设备支持情况的备选。

方案 A（首选）：UniFi UCG-Ultra + U6 Pro/U6+

① 与 S34 的接线

S34（2.5G 口）──2.5G 网线──▶ UCG-Ultra 的 2.5G WAN 口
UCG-Ultra 的 LAN 口 ──▶ PoE 交换机（或 PoE 注入器）──▶ U6 Pro / U6+
                        └─▶ 交换机其余口 ──▶ 交易 Mac / 其它有线设备

三个必须提前知道的点：

# 事项 说明
1 UCG-Ultra 只有 1 个 LAN 口（约 1×2.5G WAN + 1×GbE LAN） 多台有线设备必须再配交换机（建议带 PoE）
2 UCG-Ultra 不带 PoE U6 系列 AP 走 PoE 供电，需 PoE 交换机或注入器
3 管理方式 UCG-Ultra 自带控制器，无需另买 Cloud Key；手机 App / 网页即可

② SQM 参数（UniFi Smart Queues）

路径：UniFi Network → Settings → Internet →（你的 WAN）→ Smart Queues

项 填什么 依据
Enable Smart Queues 开 即 fq_codel 系 AQM
Download 先填 225 Mbps（实测 207–230 的约 95%） UniFi 内部再按比例整形
Upload 先填 40 Mbps（实测 41–49 的约 90%） 上行是丢包主因
若仍有膨胀 两个值各再降 10%（≈200 / 36）后复测 直到负载增量 <10 ms
若吞吐被压太低 先把 Download 调回实测值，上行保持保守 下行整形对 CPU 更重

二、dB 是什么：衡量两个功率之间的比值

dB 不是绝对单位，是两个功率比值的对数：

dB = 10 × log10( P1 / P2 )
变化 功率含义
+3 dB ×2
−3 dB ×1/2
+10 dB ×10
+20 dB ×100
+30 dB ×1000

为什么用对数：Wi-Fi 信号动态范围极大；取对数后多级损耗可以直接相加，这正是本次能"加"到 28 dB 的原因。

单位 含义 本次实测
dBm 绝对功率（相对 1 mW） 信号 −42 dBm（原 −70 dBm）
dB 相对变化/增益/损耗 变化 +28 dB
SNR（dB） 信号比噪声高多少 47 dB（原 18 dB）

5 GHz 常见 RSSI 阈值：

RSSI 体验
−30 ~ −50 dBm 极佳（本次 −42）
−50 ~ −60 dBm 很好
−60 ~ −67 dBm 可用，高 MCS 基本能跑
−67 ~ −75 dBm 开始掉档（原 −70 掉到 MCS 3）
< −80 dBm 基本不可用

SNR 一般需 ≥25 dB 才算健康（当时 18，改善后 47）。

+28 dB 的直觉换算：功率 ×630；等效"距离"约 25 倍（自由空间每翻倍距离 +6 dB，28÷6≈4.7 次翻倍）；链路档位 MCS 3 → MCS 9；下行 161–230 → 411–434 Mbps（一致）。

三、木箱各因素的实际贡献（材质不是主因）

因素 大致量级 说明
箱内近场金属：电源插排、适配器、网线 5–20 dB 距离天线 10–20 cm 内的导体与开关电源会吸收、反射并使天线失谐，最容易被忽视且最狠
四面围合形成的腔体 5–15 dB 能量被困住并被箱体吸收；腔体内形成驻波，某些方向出现零点(null)，朝 Mac 方向可能瞬时掉 20+ dB
低位 + 天线朝向受限 3–10 dB 放在箱底、周边杂物多，主瓣被挡
信道拥挤（当时 ch36） 取决于环境 36 是常用低信道，干扰多；改到 157 / 149 后明显改善
木材材质本身 约 2–6 dB/层（穿越 1–2 层即 4–8 dB） 干木是低损耗介质；湿木/含水木材差很多（水对 2.4/5 GHz 吸收强）

结论：观察到的是"近场金属 + 腔体 + 低位朝向 + 信道"合计约 28 dB，木材本身只占几分贝；换成塑料箱、金属箱只会更糟（金属箱等于法拉第笼）。

5 GHz 更敏感的原因：频率更高，穿透更差、被水与木材吸收更多、方向性更强、绕射更弱；好处是信道多、干扰少、速率高。

四、天线朝向的正确规则

偶极子天线的辐射规律：最强的方向垂直于天线本体，沿天线轴向是零点(null)。

目标 天线姿态 原理
主要覆盖楼上（正上方） 至少 1 根天线放平（水平） 水平偶极子的最大辐射方向是上下
兼顾同层四周 其余 2 根竖直 竖直时水平四周最强
两层都要 一横两竖（推荐，已采用） 上下 + 四周都有覆盖
想都沾一点 三根 45° 斜放 折中，但每个方向都不够强

极化匹配：手机/笔记本（开盖时）多为竖直极化，因此至少保留竖直天线，即"一横两竖"而非"三根全横"。

四、如何查 2 楼是否有可用同轴口（软件查不到）

同轴是无源介质，没有任何信号能让电脑探到，只能靠物理检查加一次 5 分钟实测。

步骤 做法 结论
1. 目视找口 找圆形带螺纹的 F 型接头（墙面面板，常见于卧室/客厅电视后方/壁橱，面板常标 CATV / TV / SATV） 只知道有没有口
2. 看是否已接 小心拆开面板，看线是否接在分配器(splitter)上 有 splitter 说明大概率在分配树里
3. 决定性测试（推荐） 把 S34 搬到该口接上，通电等 2–5 分钟，看 Online/DS 灯 常亮 = 该口是活的（与 Comcast 同一条线路树），MoCA 可用；不亮/闪烁 = 未接通，需在入户分配器处接上

搬机测试注意：盘后做（会短暂断网，影响 dxFeed/邮件）；判读 Power 常亮 + Online 常亮为锁定成功，闪烁为未锁定；测完搬回原位等重新锁定。

辅助工具（可选）：同轴线缆测试器（如 Hitron DSS-01）能判断线通不通/短路，但不能判断是否连到 ISP，因此第 3 步不可替代。

五、MoCA 选型（3 个硬条件）

条件 要求 原因
1. MoCA 2.5 必须 实际可达约 1 Gbps，匹配 400+ Mbps 套餐
2. 至少买 2 只 必须 一只在 modem 侧，一只在 2 楼
3. MoCA 兼容分配器 + POE 滤波器 最容易被忽略 老 splitter 只到 1 GHz 会挡掉 MoCA；POE 滤波器必须装在入户点，防信号外泄与干扰邻居

常被推荐的型号（2026）：ScreenBeam ECB7250、Hitron HTEM4/HTEM5、goCoax WF-803M、Actiontec / ASUS MA-25。

与 DOCSIS 3.1 共存注意：MoCA 占 1125–1675 MHz，而 D3.1 下行可到 1218 MHz；若出现干扰或降速，换用支持 D-High 频段（1350–1675 MHz）的适配器或调整滤波器位置。

六、接法（拓扑）

入户 coax ──[MoCA POE 滤波器]──[MoCA 兼容分配器]──┬── S34（modem，原样不动）
                                                  └── MoCA 适配器① ──网线── Archer C7 的 LAN 口
2 楼 coax 口 ── MoCA 适配器② ──网线── 2 楼电脑（或接交换机给多台设备）

要点：适配器① 接 C7 的 LAN 口（不是 WAN）——MoCA 是二层桥接，等于凭空多一根网线，2 楼电脑与 1 楼设备处于同一局域网；2 楼侧建议接一台小交换机，便于将来加 AP。

七、权衡（当前可以不做）

  • 已接受 2 楼 Wi-Fi 速度（152–171 Mbps），MoCA 非必需。
  • 唯一值得做的理由：2 楼若要做对延迟/抖动敏感的操作（下单、dxFeed 实时行情），当前短板是偶发抖动 18 ms 与负载 160 ms。
  • 成本：MoCA 2.5 双只装约 $120–180；若家里能拉网线则 $0–20 且效果最好。
  • 有利条件：家里已有同轴（S34 在用），若 2 楼有活口，MoCA 是最省事的"网线"。
